hft-lob-modeling

A four-language (Python / C++ / Rust / Java) cross-verified laboratory for high-frequency market microstructure: a price-time-priority limit order book with deterministic replay, a pinned zero-intelligence order-flow generator, univariate and bivariate Hawkes processes with exact O(N) likelihoods, Ogata thinning and time-rescaling goodness of fit, and an OFI / queue-imbalance feature pipeline feeding a neural network built from scratch with no frameworks and no RNG. Every numerical path is pinned by API_SPEC.md and held to 18 golden cases in all four languages — closed out by an honest accounting of whether the predicted signal survives transaction costs (it does not: gross +45.0 ticks, net −139.5).

What the latest review changed. The review found that the Java book stored ticks, sizes and ids as int: a 3·10⁹-tick limit price narrowed to a negative value, which the matcher read as "no price bound" and swept the entire opposite side. Every port now holds prices, sizes and ids as signed 64-bit integers end to end, the price bound is an explicit flag rather than a sentinel, and the tick conversion is pinned (round half up, 1e-9 relative grid tolerance, 1 ≤ ticks ≤ 9e18, C++ to_ticks no longer undefined behaviour). The same pass made the Hawkes fit objectives pure under exp underflow, fixed the ofi_at window boundary in C++, added label validation to signal_pnl, a dual Kolmogorov series for small λ, strict CSV readers and writers in all four ports, and the review test set PT-1 to PT-16. One caveat stated plainly: the accuracy and PnL goldens are argmax-discrete — a single flipped holdout prediction moves accuracy by 1/1305 ≈ 7.7e-4 — and pass bit-for-bit on glibc/x86-64 in all four languages, but a libm whose sin/exp differ by 1 ulp could legitimately flip a near-tie after 800 epochs; the README says to widen those tolerances to 1/n_test rather than "fix" the port.

What's inside

Limit order book

Price-time-priority matching with partial fills, market orders walking the book, crossed limits that stop at their own price, unknown-cancel and duplicate-id rejection. Prices are integer ticks (tick_size converts once at the API boundary); mid and microprice are the only doubles, with an explicit NaN guard when a side is empty (61 such events in the bundled stream).

Replay, ZI flow and CSV

Deterministic event replay with golden book snapshots; the Smith–Farmer–Gillemot–Krishnamurthy zero-intelligence generator with a pinned u1, u2[, u3] draw order; and strict readers/writers for the three CSV schemas (exact header, CRLF tolerated, only trailing blank lines, 64-bit integer grammar) so a hand-edited file fails loudly in every language.

Hawkes processes

Univariate and bivariate mutually exciting processes with an exponential kernel: Ozaki's O(N) likelihood recursion shipped next to its brute-force twin, Ogata thinning simulation (two uniforms per candidate), and MLE by a native Nelder–Mead on log-parameters that pins scipy's initial-simplex and acceptance conventions. Branching ratio and 2×2 spectral radius diagnostics warn at ≥ 0.9 and ≥ 1 rather than throwing.

Goodness of fit

Time-rescaling residuals (Brown et al. 2002; Meyer 1971 for the bivariate case) tested against Exp(1) with an exact KS statistic, Stephens' small-sample correction and two Kolmogorov series switched at λ < 0.1. On the bundled data the fitted parameters pass (KS 0.0172, p = 0.86) and deliberately wrong ones reject (p = 2e-14).

Feature pipeline

Cont–Kukanov–Stoikov order-flow imbalance (their eq. 4), queue imbalance and microprice features over event-counted windows, with 3-class direction labels at a horizon H; ofi_at(i, w) requires i ≥ w and labels outside {0, 1, 2} are rejected. Windows, lookback and horizon are counted in events, never clock time.

Neural network from scratch

A (16, 8) ReLU MLP with softmax head, logistic-regression and majority baselines, Bishop §5.3 backprop, He-scaled deterministic sin-based init, population-variance standardisation with a std < 1e-12 → 1 floor, max-shifted softmax with a 1e-300 log floor, and pinned tie-breaks (argmax → lowest index). Training loss 1.0806 → 0.6760 over 800 full-batch epochs, reproduced to 1e-8 in four languages.

Signal PnL

Trades the predicted direction on the chronological holdout mid-to-mid, charging half a spread on entry only — PnL in ticks per unit size. The bundled result is the point of the project: the classifier finds real structure and costs erase it.

Testing approach

Three layers per language: the 18 goldens, the invariant and statistical tests API_SPEC §10 requires (KS at true parameters fails to reject, near-critical DGP fits with a warning, tiny-n KS), and the post-review edge-case suite (tick-0 and 6·10¹² / 10³⁰⁰-tick prices, CSV robustness, maxiter = 1 reporting converged = false, Poisson and single-event limits, degenerate one-class labels). Tolerances are graduated: 1e-12 where arithmetic is exact, 1e-8 for pinned float pipelines, 1e-4 / 1e-3 for optimizer outputs.

Reference papers

Smith, Farmer, Gillemot & Krishnamurthy (2003) for the ZI generator; Stoikov (2018) microprice; Cont, Kukanov & Stoikov (2014) OFI; Hawkes (1971), Ozaki (1979), Ogata (1978, 1981), Bacry, Mastromatteo & Muzy (2015); Brown et al. (2002), Meyer (1971), Stephens (1970), Numerical Recipes §14.3.3; Nelder & Mead (1965), Lagarias et al. (1998), SciPy 1.0; Bishop (2006), He et al. (2015); Knuth TAOCP Vol. 2 §3.3.4 for the LCG.

Units and what is out of scope

Hawkes times and T share one arbitrary unit (seconds in the bundled data) with mu, beta per unit time and alpha per event. Not covered: timestamps and clock-time windows, calendars and sessions, reduce/replace/iceberg/auction/halt messages, fees, latency, fill probability, queue-position tracking, standard errors or Hessians for the MLE, duplicate-timestamp tie-breaking, multi-venue books. A reference and research implementation, not a matching engine or trading system.

Quick start

git clone https://github.com/AshJha0/hft-lob-modeling.git
cd hft-lob-modeling

# Python (3.11; numpy required, scipy only for three cross-check tests)
cd python
pip install -r requirements.txt          # numpy, scipy, pytest
PYTHONPATH=src python3 demo.py           # end-to-end demo
PYTHONPATH=src python3 -m pytest -q      # 101 tests incl. the golden suite
cd ..

# C++ (C++17, CMake >= 3.16, g++ 13, GoogleTest)
cd cpp
bash build.sh    # cmake configure + build (Release, -j2)
./build/demo
ctest --test-dir build --output-on-failure    # 90 GoogleTest cases
cd ..

# Rust (edition 2021, cargo 1.95)
cd rust
cargo run --release --bin demo
cargo test --release             # 94 unit + integration + golden tests
cd ..

# Java (21; JUnit 4 + Hamcrest at /usr/share/java)
cd java
bash build.sh    # javac -Xlint:all -Werror into out/
bash demo.sh
bash test.sh     # 84 tests
